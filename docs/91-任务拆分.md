# 这很三国｜任务拆分

《迭代计划》中的每个迭代，在开发前拆分为可独立开发、可独立验证的任务。约定如下：

* 编号连续，跨迭代不重排，一个任务对应一次可验证的交付
* 每个任务在自己的层内自洽，验证通过后再进入下一个
* 任务按依赖推进，依赖未完成时不开始被依赖的任务
* 所在层：`docs` 文档 ｜ `core` 规则层（不依赖 Phaser）｜ `app` 装配层 ｜ `ui` 界面外壳 ｜ `game` 表现层 ｜ `test` 测试
* 每个任务记录交付内容、验证方式与当前状态

## 三、迭代 3｜行动力与人才寻访

**T18 行动力模型**（`core`）

* `GameState` 增加当季剩余行动力；每季预算与各项行动的消耗集中定义为常量表，初值取每季 10 点、寻访 4 点，供迭代 5 按实测调整
* 结束回合时把剩余行动力重置为当季预算

* 验证：新开局与结束回合后行动力等于当季预算；扣减不会使剩余为负
* 状态：已完成

**T19 行动流程与行动记录**（`core`）

* 统一行动流程：校验前置条件 → 校验行动力 → 扣除 → 执行规则 → 更新状态 → 产生记录
* `GameState` 增加全局行动历史，记录行动类型、势力、时间、目标与结果；跨回合保留
* 验证：前置条件或行动力不满足时整体拒绝且状态不变；成功时按流程扣减并追加历史；结束回合后历史保留
* 状态：已完成

**T20 武将模型与人物数据**（`core`）

* 定义最小武将：标识、姓名、状态（在野 / 在仕 / 退场）、所属势力（可为空）；战斗属性留待迭代 4

* 入仕与否由状态决定，在野者可入仕，不由随机决定，使「发现谁」成为寻访唯一的随机环节
* 给出建安十三年的人物数据，按所在州分布，供寻访抽取
* 并入 `GameState` 与剧本，校验引用完整
* 验证：标识唯一；所属势力引用有效；状态与所属势力自洽；入仕判定不依赖随机
* 状态：已完成

**T21 人才寻访与双随机源**（`core`）

* 引入两条互不干扰的随机流：模拟流沿用现有 `randomState`，随存档落盘、可复现；抽卡流会话级、不落盘、随会话播种，读档与刷新都不回退
* 寻访只消耗抽卡流：范围以玩家势力当前占有战略点所在的州为准，本迭代该州为单一卡池，按州控制分级的卡池留待迭代 4
* 在该州在野武将中抽取候选，在野者立即入仕玩家势力，忠诚等留待迭代 7
* 前置条件含「在仕武将数未达上限」（见 T20），满员或该州无可寻之人时拒绝、不扣行动力
* 寻访以传入的随机源为参数，规则层保持不依赖会话的纯函数
* 验证：范围外的武将被排除；满员或无可寻之人时明确失败且不扣行动力；同一抽卡源下结果可复现；读档后重复寻访会消耗抽卡流的下一个值，不复现上一候选
* 状态：已完成

**T22 界面：行动力、寻访与行动记录**（`ui`、`app`）

* `GameSession` 暴露寻访接口；侧栏显示本季剩余行动力与近况，寻访按钮放在人才弹窗，行动历史另有弹窗

* 验证：操作验证：寻访后行动力、历史与麾下武将同步刷新；行动力用尽后无法再寻访
* 状态：已完成

## 四、迭代 4｜核心玩法垂直切片：最小战斗闭环

* 接边按几何推导并入，并排除两条不合理的长边（临淄—小沛隔兖、徐，晋阳—蓟隔冀州），最终为：临淄—南皮·濮阳、晋阳—邺、蓟—南皮、番禺—桂阳

* 存档版本递增——地理数据随存档落盘，不升版会读到旧版天下
* 验证：数据自洽；四个新点只有上述接边；每个新点落在所属州轮廓内；从江夏可达全部战略点

**T26 州归属模型与重算**（`core`）

* `Province` 增加归属势力字段，并入 `GameState` 与存档；本轮由数据直接给出建安十三年的初始归属（曹操据司隶、豫、兖、徐、青、冀、并、幽、荆，孙权据扬，益、凉、交无归属）
* 判定：占该州战略点最多者为归属势力，无主战略点不计入比较；与他方并列时，原归属在并列者之列则保持，否则判为无归属；一州无任何势力占点则无归属
* 归属与过程相关（同样版图可能因原归属不同而结果不同），存状态而非纯推导；重算函数供占地流程调用
* 存档版本递增，旧存档失效
* 验证：初始归属自洽且与占点多寡一致；并列保持原归属、并列而原归属不在其中转无主、优势易手、州内无势力转无主；存档往返一致
* 状态：已完成

**T27 战略点图标调整**（`game`）

**T29 势力粮食、部队与征兵**（`core`）

* 验证：征兵后目标武将兵力增加、势力粮食减少；粮食不足被拒；调动只在相邻自有战略点间成立；武将每回合的行动次数受限
* 状态：已完成

**T30 进攻与战斗引擎**（`core`）

* 新增进攻行动：驻守的武将带兵攻击其相邻的一个他方或无主战略点，自动结算
* 战斗以公式直接判定，不做战斗环节：攻方战力取投入兵力 × 武将加成，守方取守军兵力 × 守将加成 × 防守补正，士气参与战力计算；由战力比得出胜负、伤亡与剩余兵力；兵力占优的一方可以击败能力更强但兵力不足的一方
* 士气由单挑改变：一方提出单挑，对方拒绝则其士气下降，应战则胜者升、败者降；单挑致阵亡留待迭代 7，士气数值待定
* 公式预留扩展位（战前策略、地形、兵种），将来加入具体战斗操作时不必重写
* 胜则目标战略点归属转为攻方、部队前移进驻新战略点；败则部队退回原驻地并受损；战斗不改变地理结构
* 验证：固定种子下同一场战斗结果稳定；兵力占优可胜能力强者；防守补正与士气影响生效；单挑改变士气；胜则前移、败则退回；占领后战略点归属改变；不改变地理结构
* 状态：已完成

**T31 州控制分级与寻访卡池**（`core`）

* 为人物数据标注卡池层级（基础 / 二级 / 三级）
* 寻访卡池按玩家对该州的控制分级：占该州至少一个战略点开基础池，成为该州归属势力开二级，占该州全部战略点开三级；名将置于高层
* 荆襄等在野名士置于基础池，保证刘备据江夏时可在荆州寻得
* 验证：控制程度不同则候选集合不同；低层不会提前放出高层人物；固定种子可复现
* 状态：已完成

**T32 界面：征兵、调动、进攻与战报**（`ui`、`app`）

* 验证：操作验证：能从寻访走到征兵、进攻、占领，行动力、地图与历史同步刷新；选将时可见武力、统率与智谋
* 状态：已完成

## 五、迭代 5｜核心玩法验收

本迭代是验收关卡，不扩展玩法。为了让验收有固定、可反复的起点，先补一个固定测试开局与开局入口；随后是实际游玩与判断，验收中暴露的问题就地以调整任务处理（T38–T45），不另开迭代。

**T36 验收开局与新游戏入口**（`core`、`ui`、`app`）

* 新增验收开局「荆扬一隅」：三家势力、两个州、十个战略点，资源从简；地理与人物数据取自正式剧本（地理按真实邻接截取），只缩小规模
* 汇集剧本清单，界面加入「新游戏」入口，可选择剧本重开一局；重开覆盖自动存档，不影响手动槽位
* 验证：验收开局的地理与人物数据自洽；重开后回合、历史与自动存档均重置
* 状态：已完成

**T37 核心玩法验收记录**（`test`）

* 用验收开局从玩家视角连续游玩十到二十季，记录行动力取舍、战斗判断、地图变化与继续游玩意愿
* 产出一份简短验收笔记，回答迭代 5 的四个问题；据此决定调整玩法，或进入迭代 6
* 验收结论：
  * **行动力取舍成立**：三件事排满一季，常见组合不再剩下花不出去的行动力（费用按 T44 调整后）
  * **战斗判断空间不足**：反复失利本身不是问题（四成损失已经可承受），问题是攻不动时只能干等，一连数季无事可做
  * **地图变化有意义**：占城改归属，粮产随领地增长，扩张有回报
  * **继续游玩意愿成立，但内容单薄**：核心循环能跑通一局，缺的是「除了征兵与进攻还有别的事可做」
* 判定：核心循环成立、内容单薄。瓶颈不在数值，不返工调参；按既定顺序进入迭代 6，让其他势力自主行动，为世界提供变化
* 已知缺口：坚城攻不下（见 T45）、士气恒定（单挑无入口）、粮食不消耗
* 状态：已完成

**T38 核心循环调整：兵力自然增长与征兵按内政**（`core`、`ui`）

* 新增每季自然增长：各势力在仕武将按统率补充兵力，产量带固定幅度的浮动；增量只与统率有关、与当前兵力无关，避免差距随回合放大
* 征兵改为应急手段：产量按该武将的内政换算、粮食按同一基准消耗，并占用该武将本季的行动；界面对已行动者停用征兵按钮
* 验证：自然增长按统率浮动且只在仕者参与；征兵产量随内政变化、占用行动次数；固定种子下可复现
* 状态：已完成

**T39 守军迎战编成**（`core`）

* 守军改为至多三人迎战：从该战略点的守军中取兵力最多的三名，统率最高者为主将、智谋最高者为军师，已行动者只计半数兵力
* 只接战的双方受损；未接战的守军不受战损，但战略点失守时同样撤退。避免败军退守堆在一处、最后一城的守军无止境地变强
* 验证：守军超过三人时只按三人计战力；已行动者折半；未接战守军不计入战力与伤亡
* 状态：已完成

**T40 守军败退去向**（`core`）

* 战略点失守后，守军每名武将按同一套权重判定去向：约一半撤往自有的战略点，其余战死、被俘各占一半；覆灭之战也不例外
* 君主只在本势力尚未覆灭时必定撤退；本势力再无城池可投时，逃亡者流落为在野（卡池层级暂给基础池），将来可被寻访、复起
* 被俘的处置（招降、释放、处决）尚未实现，暂按战死退场；逐将的具体行为留待迭代 7
* 验证：君主在势力未亡时必撤退、覆灭之战不再豁免；无城可投时或在野或退场；固定种子下可复现
* 状态：已完成

**T41 势力覆灭标记**（`core`、`ui`）

* `isFactionDestroyed` 判定势力是否覆灭：失去全部战略点，或麾下不再有任何在仕武将
* 势力栏在图例中为覆灭的势力标出「已覆灭」
* 验证：尚有地盘与部属时未覆灭；失去全部战略点或部属尽失时标出
* 状态：已完成

**T42 核心玩法推演工具**（`tools`）

* `npm run acceptance` 用规则层无画面跑固定种子的整局，输出逐季日志（行动力、兵力、粮、各势力在仕人数与覆灭标记）与汇总（覆灭势力及其季数、武将去向、终局版图）；敌方尽灭或玩家覆灭即提前收尾
* 推演用一个规则驱动的玩家代理（寻访 → 进攻 → 征兵 → 征粮 → 朝主攻目标逐跳行军），不代表最优打法，只用来观察数值松紧与局势走向；脚本同时校验同种子重复推演结果一致
* 验证：`npm run acceptance` 可复跑并输出报告；`npm test` 不含该脚本
* 状态：已完成

**T43 粮食与兵力增长调整**（`core`、`ui`）

* 新增征粮行动：派一名部属征收，产量按该武将内政与其势力自有战略点数浮动，占用 3 点行动力与该武将本季的行动
* 粮食来源改为「领地粮产（大幅下调）＋主动征粮」，不再只靠领地自动增长；每季粮产降为城市 300、关隘 150、野地 100
* 征兵改回由统率影响（兵强马壮者征兵也多），粮耗同步；每季自然增长的基准由统率 5 兵降为 2 兵
* 界面上「征兵」旁增加「征粮」，已行动者两者一并停用
* 验证：征粮入库且占用行动；征兵产量随统率；粮产与自然增长按新值；固定种子下可复现
* 状态：已完成

**T44 行动力费用与战败损失调整**（`core`）
* 行动力费用改为：进攻 4、寻访 3、征兵 3、征粮 2、调动 2。一季 10 点，寻访、进攻、征兵三件事正好排满，不再出现剩余行动力无处可用
* 战败损失由六成降为四成（胜方仍为两成）：一次攻城失利不再打残主力，避免一蹶不振
* 验证：`npm test` 通过；`npm run acceptance` 仍能打到敌方尽灭
* 状态：已完成

**T45 胜方伤亡缩放与带兵上限**（`core`、`ui`）
* 胜方伤亡改为按双方战力比缩放：胜方伤亡率 = 两成 ×（敌方战力 ÷ 我方战力），碾压局几乎不流血。原来不分强弱一律两成，15000 打 3000 反而比对方损失更多
* 每名武将新增带兵上限（统率 × 150）：自然增长与征兵都补到上限即止，满员后不能再征兵；兵力堆在一人身上不再是无代价的最优解
* 武将卡片显示「兵 当前 / 上限」
* 已知缺口：双方都撞上限后，守军的防守补正可能压过攻方的质量优势，形成攻不下的坚城。破局手段（兵种、计略、围城）留待后续迭代
* 验证：`npm test` 通过；`npm run acceptance` 复跑，堆兵被上限截住、碾压伤亡随战力比下降
* 状态：已完成

## 六、迭代 6｜世界自主运行

本迭代让其他势力按最小行为集自主行动，天下不再只由玩家推动。行动力改为按势力独立计算，并补一层最小的势力关系让开局有敌我之分，是这一迭代的前置改造。

**T46 行动力按势力独立**（`core`、`ui`、`test`）

* `GameState.actionPoints` 由单一数字改为按势力存放；`runAction` 从发起行动的势力名下扣除，玩家各动作的调用方式不变
* 存档 `schemaVersion` 递增（16 → 17）
* 验证：各势力行动力独立消耗与恢复；旧档按版本失效
* 状态：已完成

**T47 行动泛化为按势力执行**（`core`）

* 动作不再写死玩家势力：`recruit`、`harvestGrain`、`transfer` 按武将所属势力，`seekTalent` 按战略点归属，`attack` 按主将所属势力；`isAttackable`、`attackCandidates`、`officerBlockedReason` 增加可选的行动势力参数，缺省仍为玩家，界面口径不变
* 验证：既有测试全绿（玩家侧行为不变）；同一动作可由任意势力执行
* 状态：已完成

**T48 其他势力的最小行为集**（`core`）

* 新增 `factionAi`：`runFactionTurns` 让每个非玩家、未覆灭的势力每季按寻访 → 进攻 → 征兵出手，只调用既有动作
* 攻击目标取「邻接、可胜、价值最高、守备最弱」者；随机取自随存档落盘的模拟流，固定种子下可复现
* 验证：他方会征兵、寻访、进攻；同种子行为序列一致
* 状态：已完成

**T49 回合收尾接入他方行动**（`core`、`ui`、`tools`）

* 回合收尾改为「其他势力行动 → 世界结算 → 进入下一季」（`turn.endTurn`），`GameSession` 与推演脚本走同一流程
* 他方行动写入历史，界面按势力分组展示（历史渲染无需改动）
* 验证：结束回合后历史出现他方条目；`npm run acceptance` 反映含他方的局势
* 状态：已完成

**T50 迭代 6 验证与文档同步**（`test`、`docs`）

* 补 `factionAi` 测试：他方行动与进攻、玩家不参与、同种子可复现、行动力互不占用
* 同步《游戏机制》（其他势力一节）与《技术设计》（行动力按势力、世界模拟）
* 验证：`npm test` 全绿；`npm run acceptance` 复跑一致
* 已知：推演代理在两三家混战里被削弱——根因在开局态势，由 T51 处理；其余他方强弱与行为细节待实玩判定，必要时回到 T48 调
* 状态：已完成

**T51 势力关系（最小）**（`core`、`ui`）

* `GameState` 增一张势力对关系表（同盟 / 敌对，未声明为中立），开局取自剧本；查询集中在 `relations`（`areAllied`、`areHostile`、`relationBetween`）
* 作用只两条：同盟之间不能开战（`isAttackable`、`attackCandidates`、`attack` 一并排除）；他方只对敌对势力或无主战略点用兵。侧栏的势力列表为每个他方标出「同盟」或「敌对」
* 三国 208 开局：刘孙同盟，刘曹与曹孙敌对。结盟、宣战、停战等外交动作留待迭代 9
* 关系随存档落盘，`schemaVersion` 由 17 升至 18
* 验证：同盟目标不可进攻；他方不碰同盟与中立；侧栏标出关系
* 状态：已完成

**T52 守将去向与伤亡调整**（`core`）

* 战略点失守后，逐名守将的去向写入行动记录——撤往何处、战死、被俘、流落为在野——在「历史」与战报可见
* 伤亡率下调：逃亡由五成提高到七成五，战死由两成五降到一成五，被俘由两成五降到一成
* 修一处缺陷：`provinceControl` 原先固定按玩家势力评判，他方寻访因此误用了玩家的州控制度，能抽出本不该放出的高层人才；改为按发起寻访的势力评判
* 验证：`npm test` 全绿；`npm run acceptance` 复跑一致
* 状态：已完成
