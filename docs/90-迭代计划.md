# 这很三国｜迭代计划

## 一、总体安排

项目从零开始，以迭代方式推进，目标是达到 [项目概览](00-项目概览.md) 中定义的初版。

每个迭代交付一个可以运行、可以观察的结果，而不是完成某一层代码。每个迭代按本节末尾的方式验证通过之后，才开始下一个迭代的开发；验证不通过就在本迭代内修正，不把问题带入下一个迭代。

迭代顺序遵循一条原则：先把一局游戏按月循环起来，再逐步往循环里加入世界、人物、军队与行动，最后处理事件、胜负与收口。

每个迭代都遵守 [技术设计](20-技术设计.md) 的架构约定：规则层不依赖 Phaser，可以在没有画面的情况下独立运行；随机数集中管理并支持固定种子。

验证方式按迭代内容选择，通常有三类：

* 操作验证：在浏览器中执行某个操作，观察界面结果
* 复现验证：用固定随机种子重复运行，比较结果是否一致
* 规则验证：不启动画面，直接运行规则层，检查状态变化是否符合设计文档

## 二、迭代清单

### 迭代 1｜骨架与回合循环

**做什么**

* 建立 TypeScript、Vite、Phaser 的工程结构，接入 GitHub Pages 自动部署
* 定义最小的 `GameState`（日期、回合数、势力）与集中管理的随机数模块
* 实现结束回合：月份推进、势力轮转、界面刷新
* 界面只保留当前年月、势力列表与结束回合按钮

**如何验证**

* 本地启动后浏览器能打开，推送之后 Pages 地址能访问
* 连续结束回合，年月正确递增，势力列表稳定显示
* 规则层可以在不启动画面的情况下推进指定月数且不报错

### 迭代 2｜势力与州郡

**做什么**

* 建立州、郡数据与势力领土，实现郡的占有与州的归属，包括无归属状态
* 地图界面：按势力着色显示郡，标出州的划分
* 其他势力按最小行为集行动（征兵、建设、寻访），暂不含战争
* 其他势力的行动写入历史记录并展示给玩家

**如何验证**

* 地图能正确显示各郡的占有情况与各州的归属势力
* 连续推进回合，能看到其他势力可读的行动记录
* 人为改动某州最后一个郡的归属后，州归属按 [产品设计](10-产品设计.md) 的规则重算，出现并列时该州变为无归属
* 固定种子下重复运行，其他势力的行为序列一致

### 迭代 3｜行动框架与人才寻访

**做什么**

* 行动力：成本集中定义，行动流程为校验前置条件、校验行动力、扣除、执行规则、更新状态、产生记录
* 接入第一个行动：人才寻访
* 界面显示本月剩余行动力与已执行行动

**如何验证**

* 行动力不足时该行动无法执行，并有明确反馈
* 寻访消耗正确的行动力，产生候选人物并写入记录
* 进入下月后行动力恢复为当月预算
* 固定种子下寻访结果可复现

### 迭代 4｜武将系统

**做什么**

* 武将属性与状态（在野、在仕、被俘、退场）
* 势力倾向与忠诚的计算，作用于加入、留任与招降
* 在野武将与人才寻访打通，提供武将列表与详情界面

**如何验证**

* 寻访到的武将按各自的意愿与处境正确出现
* 招降结果随势力倾向与忠诚变化，且能说明是什么因素导致的
* 退场武将不再出现在任何列表与结算中

### 迭代 5｜部队、征兵与粮食

**做什么**

* 部队：所属武将、兵力、兵种、士气、位置
* 征兵：受人口与粮食约束，兵力直接编入指定部队
* 每月结算粮食收支，部队按规模消耗粮食

**如何验证**

* 征兵后目标部队兵力增加，人口与粮食按规则减少
* 粮食不足时能观察到明确后果（后果规则见第三节）
* 征兵与粮食结算在固定种子下可复现

### 迭代 6｜战斗与进攻

**做什么**

* 战斗引擎：接收双方部队与环境，输出胜负、伤亡、剩余兵力、士气变化、主将状态、占领结果与战斗日志
* 进攻郡：战前选择、自动结算、占领或失败
* 占领后触发州归属重算
* 战报展示

**如何验证**

* 固定种子下同一场战斗的结果稳定
* 兵力占优的一方可以击败能力更强但兵力不足的一方，与 [产品设计](10-产品设计.md) 的描述一致
* 占领郡之后，地图与州归属同步更新
* 更换战斗展示不影响战斗结果，战斗规则与战斗表现确实分离

### 迭代 7｜内政、外交与人事

**做什么**

* 内政的三项建设
* 外交：结盟、停战、提升关系、索取或给予资源、劝降、宣战
* 人事：任免、调任、赏赐、处置被俘武将
* 外交关系接入其他势力的决策

**如何验证**

* 三类行动各自生效、消耗行动力，并能在记录中追溯
* 外交关系的变化会影响其他势力的后续行为
* 处置被俘武将的招降、释放、处决三条路径结果符合规则

### 迭代 8｜事件系统

**做什么**

* 数据驱动的事件结构：触发、权重、条件、效果、文本
* 系统事件与人物事件，人物事件可以包含玩家选择
* 事件效果与事件展示分离

**如何验证**

* 满足条件时事件按权重触发，效果只落在已有属性与状态上
* 新增一个事件只需要增加数据，不修改代码
* 需要玩家选择的事件能在界面上完成选择并完成结算

### 迭代 9｜存亡、继位与胜负

**做什么**

* 势力灭亡：失去全部地盘，或不再有任何武将
* 君主阵亡后的继位与野心惩罚
* 胜利判定与结束结算界面

**如何验证**

* 清空某势力的全部郡或全部武将后，该势力灭亡并退出世界
* 君主阵亡后由声望最高的武将继位，野心最高的武将同时被处死
* 达成统一后出现结算界面，一局结束

### 迭代 10｜存档与收口

**做什么**

* 存档层与本地自动存档：回合结束自动保存，重新打开可继续
* 存档带版本号
* 数值与节奏调整，占位美术替换为正式资源，完整通关

**如何验证**

* 关闭页面后重新打开，从上次结束的回合继续
* 从开局到统一完整走完一局，没有阻断性错误
* 线上版本与本地表现一致

## 三、需要先定的规则

以下内容会直接决定对应迭代能否验收，需要在迭代开始前定下来：

* 粮食耗尽后的后果，决定迭代 5 的验收方式
* 金钱的用途，决定迭代 7 中内政与赏赐的设计
* 获得州归属的具体收益，影响迭代 2 之后各势力决策的权重

其余待定项（关系系统、野心家系统、多周目、在线能力）都属于初版之后的范围，不阻塞任何迭代。
