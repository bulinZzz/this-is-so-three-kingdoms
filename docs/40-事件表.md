# 这很三国｜事件表

## 一、本文档的用途

事件用于在规则系统内制造变化、体现三国人物与题材特色、增加游戏趣味。

事件的内容属设计决策：一条事件的主题、触发条件、权重、效果与文本，先在这里写成候选并定稿，再落进事件数据。三份文档的分工：

* 《产品设计》记事件的意图与边界：三类事件（系统 / 人物 / 趣味），效果只作用于已有的属性与状态
* 《游戏机制》记已生效的规则与数值
* 本文档记事件的条目本身，以及每条从候选到落地的状态

## 二、条目状态

* **候选**：已写出，待确认
* **已确认**：内容定稿，待实现
* **已落地**：已进数据，可在游戏中触发

未经确认的条目不得写入数据。

## 三、触发方式

事件在每季结算前求值一次：筛出条件全部满足、权重为正，且未曾触发过（一次性事件）的条目，按权重抽一件施加，写一条不属任何势力的行动记录。一季至多一件，权重因此是条目之间的相对稀度。

## 四、一条事件的写法

一条事件写明六项：

| 项 | 含义 |
| --- | --- |
| `id` | 标识 |
| `text` | 触发时写入历史的一句话 |
| `once` | 触发一次后不再候选；不写则可反复触发，稀度由条件与权重自限 |
| `weight` | 权重，同季候选之间的相对稀度 |
| `conditions` | 触发条件，全部满足才成为候选 |
| `effects` | 效果 |

条件与效果是固定词表，写一条事件只从中取用；若要落到词表以外的地方，说明这条事件需要新机制，须先在设计层面确认。

**条件**

| 条件 | 写法 | 成立判据 |
| --- | --- | --- |
| `date` | `from` / `to` | 当前日期落在区间内 |
| `factionAlive` | `factionId` | 该势力尚在，未覆灭 |
| `relation` | `factions`、`is` | 两势力关系为 `ally` / `hostile` / `neutral` |
| `favor` | `factions`、`below` / `above` | 两势力好感低于 / 高于某值 |
| `resource` | `factionId`、`grainBelow` / `moneyBelow` | 该势力粮食 / 金钱低于某值 |

**效果**

| 效果 | 写法 | 作用 |
| --- | --- | --- |
| `setRelation` | `factions`、`to` | 设定两势力关系 |
| `adjustFavor` | `factions`、`delta` | 增减两势力好感 |
| `adjustGrain` | `factionId`、`delta` | 增减粮食 |
| `adjustMoney` | `factionId`、`delta` | 增减金钱 |
| `adjustLoyalty` | `characterId`、`delta` | 增减某武将的忠诚 |
| `adjustAffinity` | `characterId`、`factionId`、`delta` | 改某武将对某势力的偏好 |

词表当前的缺口：人口、兵力、民心与士气都没有落点。本轮不扩词表，事件只从中取用；凡「流民来归」「灾荒折丁」「民心涨落」一类题材，须先把对应机制补进词表，属改代码，不是纯内容扩展，故不在本轮落地。
